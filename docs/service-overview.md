# Веб-почта mailadmin: что есть, что сделано, что улучшить

Состояние на 19.09.2026. Документ живой: его правят вместе с кодом.

Дополняет два соседних: [reliability-review-2026-09-19.md](reliability-review-2026-09-19.md)
(как искали слабые места и что нашли) и [../TODO.md](../TODO.md) (что отложено и почему).

## 1. Что это

Своя веб-почта и админка вместо SOGo и iRedAdmin: Laravel 11 + Inertia + Vue 3 поверх
iRedMail (Postfix, Dovecot, Amavis, SpamAssassin, ClamAV). 258 маршрутов, 15 задач
по расписанию, 69 автоматических проверок.

| | сервер | домен | ящиков | почты |
|---|---|---|---|---|
| боевой | 192.168.30.111 | mail.innotec.su | ~112 | 188 ГБ |
| второй | 192.168.100.93 | mail.deltaservices.ru | немного | 43 МБ |

Приложение в `/opt/mailadmin`, отдаётся через Octane (RoadRunner, 11 рабочих процессов),
nginx проксирует. Копия для тестов — `/opt/mailadmin-test`.

## 2. Что умеет

### Почта

- **Список и чтение.** Страницы по 40 писем, порядок по дате письма (а не по внутреннему
  номеру), отбор: непрочитанные, с флажком, с вложениями, по метке. Письмо открывается
  не скачиваясь целиком — состав берётся из структуры, тело дочитывается частями
  (2718 мс → 131 мс, 150 МБ → 1,5 МБ на тяжёлом письме).
- **Переписка.** Письма одной цепочки собираются по ссылкам, а где отправитель их не
  проставил — по теме и собеседнику. Письма из «Корзины» и «Спама» в цепочку попадают,
  но помечены, где лежат.
- **Поиск.** По папке и по всем папкам сразу, включая общие папки коллег, «Спам» и
  «Корзину». Операторы: `от:`, `кому:`, `тема:`, `есть:вложение`, `файл:`. Поиск по
  именам файлов и признаку вложения идёт по структуре письма, а не по заголовкам —
  Dovecot с `fts_enforced = body` на заголовки не отвечает вовсе. Общий срок 12 секунд,
  по 3 секунды на папку; необойдённые папки перечисляются прямо в интерфейсе.
- **Отправка.** Вложения, ссылки через облако для больших файлов, подпись, отложенная
  отправка, окно «Отменить», напоминание «нет ответа», запрос уведомления о прочтении,
  отправка от имени общего ящика.
- **Вложения.** Просмотр картинок и PDF в почте, офисные документы показываются через
  LibreOffice как PDF, всё вместе — одним архивом. SVG отдаётся только файлом: показанный
  в домене почты, он получил бы доступ к сеансу.
- **Папки и метки**, правила разбора (sieve) с автоответом, отложенные письма,
  карантин, общий доступ к папкам.

### Календарь и контакты

Свой CalDAV/CardDAV (sabre/dav): календари, события с повторами и приглашениями, занятость
участников, задачи (VTODO), адресные книги, общая книга сотрудников и контактов компании,
история адресов. Телефоны и Outlook подключаются по тем же адресам.

### Админка (отдельный порт 8443)

Домены и DNS-проверки, ящики и псевдонимы, рассылки, подразделения, очередь Postfix,
журналы, антиспам (уровни, чёрные и белые списки, обучение, карантин), лимиты и fail2ban,
резервные копии, администраторы и роли, сертификаты, отчёты, обращения, страница
«Состояние» с проверками.

### Безопасность

Двухфакторная защита (TOTP), пароли для почтовых программ, список активных сеансов
и последних входов, свой счётчик неудачных входов плюс fail2ban по нашему журналу,
очистка HTML входящих писем, разделение зон «почта» и «админка» по портам.

## 3. Что сделано 18–19 сентября

### Разбор случая «почта письма удаляет сама»

Сотрудник пожаловался, что переслал письмо коллеге с телефона, а в «Отправленных» его нет.
По журналам: письмо ушло и было доставлено, копию в «Отправленные» не загрузил клиент —
связь рвалась, Postfix четырежды зафиксировал обрыв на 1,2–1,9 МБ. Отправка и сохранение
копии — две независимые операции, обе делает клиент, сервер их не связывает.

Из этого вышел общий признак, по которому дальше искали всё остальное: **где результат
зависит от второго шага, который может тихо не выполниться, а человеку сказано, что всё
хорошо.**

### Найдено и устранено по этому признаку

| Что | Чем было плохо |
|---|---|
| Копия в «Отправленные» из нашей веб-почты | Сбой уходил только в журнал: письмо у получателя, в папке пусто. Теперь очередь `webmail_sent_retry` и досылка со сверкой по Message-ID |
| Отложенная отправка | Одна попытка, «не отправлено» навсегда, без уведомления, черновик уже удалён. Теперь 6 попыток, уведомление, счёт в значке |
| Окно «Отменить отправку» | Письмо жило только во вкладке; при уходе досылалось через `fetch(keepalive)`, а тот не тянет тела больше 64 КБ — письмо с вложением терялось всегда. Теперь черновик сохраняется до отсчёта, а тост говорит «Отправляем…» |
| Проверка «Резервная копия» | Горела зелёным при выключенном копировании почты |
| Ошибки служб | `sa-update` десять дней не обновлял правила, systemd рапортовал успех. Теперь красные проверки состояния уходят письмом администратору |
| Журнал Postfix | Хранился 4 недели против 10 у Dovecot — разбор старых жалоб был невозможен |
| `update.sh` | Обновлял сам себя, и правки применялись со второго запуска: logrotate полдня простоял с дублем и не ротировал ничего системного |
| Пустые вложения | Мобильный клиент при обрыве оставляет заголовки вложения с `size=0`. Почта показывала их как файлы «1 Б» — скачиваешь пустышку. Теперь «файл не дошёл» |
| Вкладка «Вложения» | Всегда пустая: отбор шёл поиском по заголовку, а Dovecot с `fts_enforced = body` на заголовки не отвечает |
| `/mail/api/message/INBOX/0` | Отвечал 500 «Server Error». Теперь номер меньше единицы отсекает маршрут, а прочие ответы php-imap становятся понятным 502 |
| Большое вложение | Принималось до 256 МБ на файл при пределе письма 40 МБ: заливаешь двести мегабайт и только потом получаешь отказ |

### Разбиение кода

Правило: разделение не меняет вызовы снаружи. Тела методов переносит скрипт — он же сам
находит перекрёстные вызовы. Руками нельзя: в девятистах строках опечатка даёт тихую
поломку, а составленный руками список перекрёстных вызовов уже подвёл (DavTasks звал
уехавший метод, календарь отдавал 500).

| Было | Стало |
|---|---|
| `DavStore` 919 | фасад 274 + `DavAccess` 85, `ContactBooks` 271, `Calendars` 262, `DavTasks` 146, `DavSharing` 120, `DavProvisioning` 143 |
| `MessageReader` 679 | фасад 109 + `MessageFetch` 35, `MessageBody` 254, `ThreadBuilder` 241, `MailAttachments` 206, `MailAddresses` 28 |
| `MessageListing` 573 | 270 + `ImapQuery` 246, `MessagePage` 126 |
| `Outgoing` 458 | 195 + `MailBuilder` 268, `MailAddressList` 90 |
| `Calendar.vue` 1010 | 624 + `dates.js`, `useCalendarData`, `useCalendarLayout`, `useEventForm`, `useEventDrag`, `useFreeBusy`, `useCalendarTasks` |
| `Settings.vue` 717 | 570 + `useSecuritySettings`, `useMailRules` |
| `Contacts.vue` 573 | 453 + `useContactForm`, `useContactActions` |

Раньше уже были разложены `MailStore` (1772 → 352), `Inbox.vue` (1204 → 744) и
`SettingsController` (749 → 192).

### Чем это удерживается

- **`PartsWiringTest`** — каждый вызов между частями и каждая ссылка на константу обязаны
  разрешаться. Написан по живой поломке календаря; позже поймал ещё две мёртвые ссылки
  на константы, из-за которых падал поиск по всем папкам.
- **`DavStoreFacadeTest`** — сверяет подписи методов фасада с частями, следит, чтобы фасад
  только передавал вызов дальше и чтобы части не ссылались на фасад обратно. Поймал
  потерянные импорты дат.
- **`VueSetupOrderTest`** — обращение к значению до его объявления в `<script setup>`.
  Самая дорогая ошибка в интерфейсе: страница не рисуется вовсе, в журнале пусто.
  Случалась трижды. Проверено на живом примере: возвращаешь ошибку — проверка падает.
- **`MailAddressListTest`** — разбор строки адресатов, включая запятую внутри имени.
- Браузерные проверки: сквозная почта, календарь, контакты, правила, настройки, поиск,
  окно «Отменить». Лежат в `ux/`, запускаются `python ux/_имя.py`.

### Проверка на прочность через веб

Проверялось под обычным сотрудником. Держится: чужие папки, календари и книги контактов
недоступны (403/404), админка с почтового порта не открывается, очистка HTML убирает
`script`, `onerror`, `onload`, `javascript:`, `iframe`, `form`, `object`, `meta refresh`,
`base`, `style` и `position:fixed`, сохраняя текст письма и добавляя `rel=noopener`;
перевод строки в адресе отклоняется, в теме — не превращается в чужой заголовок;
предпросмотр офисных документов запускает LibreOffice без оболочки, с белым списком
расширений и ограничением по размеру; подделка запроса отсекается проверкой источника
(`Sec-Fetch-Site`) и ключом; увода на посторонний сайт нет; вход ограничен своим счётчиком
неудач и fail2ban.

Под нагрузкой (шесть тяжёлых поисков разом) лёгкие запросы отвечали за 88–141 мс против
119 мс в покое — один тяжёлый запрос не занимает сервис целиком.

## 4. Что можно улучшить

По убыванию важности.

1. **Резервная копия самой почты.** Её нет: 188 ГБ не копируются никуда, в архив идут
   только база и настройки. Просто включить нельзя — копия не поместится на тот же раздел.
   Нужно выбрать место (отдельный диск, NAS, снимки ВМ, borg/restic). Владелец решил
   вернуться к этому после отладки почтовика; до тех пор проверка горит красным и шлёт
   письмо. **Это главный оставшийся риск, и он принят сознательно.**
2. **Серверная копия отправленного в «Отправленные».** Сейчас копию кладёт клиент, и
   сторонние клиенты будут её ронять и дальше. План в TODO: скрытая копия через Postfix
   плюс разбор служебного ящика со сверкой по Message-ID.
3. **Второй канал уведомлений.** Всё уходит почтой; в аварии «почта не работает» канал
   не работает тоже. Нужен Telegram или SMS.
4. **Восстановление ни разу не проверялось.** Копия базы делается, но из неё не
   разворачивались. Копия, из которой не восстанавливали, — это предположение.
5. **Квоты отдельных ящиков не под наблюдением.** Диск целиком — да, переполненный ящик
   одного человека — нет, а при достижении квоты входящие отбиваются.
6. **Приём почты разобран поверхностно.** Правила sieve, карантин, серый список — там та же
   схема «второй шаг»: если правило не встало, письма тихо лежат не там.
7. **Окно «Отменить отправку» по-хорошему должно жить на сервере.** Сейчас черновик
   спасает текст, но письмо всё ещё уходит из вкладки. Правильное решение — придержать
   письмо на сервере несколько секунд, как делает Gmail.
8. **Шаблоны страниц админки** (`Settings/Index.vue`, 616 строк) — это восемь независимых
   вкладок в одном файле. Разделение возможно, но требует протянуть десятки свойств,
   а проверок на интерфейсе нет; пользы меньше, чем риска.
9. **136 неразобранных «проглоченных» исключений** из `scan_catch.py`: разобраны выборочно,
   по пути отправки. Стоит пройти остальные, особенно в DAV и в API почты.
10. **Нет проверок на самом фронтенде.** Всё держится на браузерных прогонах, а они
    медленные и требуют живого сервера. Небольшой набор модульных проверок для композаблов
    (`useCalendarLayout`, `useMailRules`) окупится быстро.

## 5. Оптимизация: что измерено и что сделано

Мерили не синтетику, а живую нагрузку — nginx пишет время каждого ответа
(`/var/log/nginx/mailweb.timing.log`, формат задан в `conf-enabled/00-mailadmin-timing.conf`).
На 78 474 записях картина оказалась такой:

| запрос | вызовов | среднее | худшее |
|---|---|---|---|
| `/mail/api/status` (опрос новой почты) | **48 630 — 62% всего** | 0,069 с | 1,41 с |
| `/mail/api/list/INBOX` | 286 | 0,108 с | 3,45 с |
| `/mail` (страница) | 121 | 0,199 с | 0,55 с |
| `/mail/api/message/N/thread` | 38 | 0,154 с | 0,59 с |
| `/mail/api/message/N` | 43 | 0,112 с | 0,33 с |

Худшие случаи списка — это поиск по всем папкам, у него свой срок в 12 секунд; 3,45 с
укладывается в задуманное. Всё остальное быстрое. **Вся нагрузка — в опросе.**

Разложили опрос по частям: подключение к IMAP 38 мс, `STATUS` папки 11 мс,
**разбор календаря 40 мс**. Календарь перебирался ради напоминаний о встречах — все
события на двое суток вперёд, чтобы найти будильник в окне в две с половиной минуты.
Срабатывает несколько раз в день, считалось сорок восемь тысяч раз.

Сделано:

1. **Запоминаем время ближайшего будильника** и до него календарь не открываем. Метка
   сбрасывается при любой правке события и живёт не дольше пяти минут — чтобы встреча,
   заведённая коллегой в общем календаре, не осталась незамеченной.
2. **Опрос стал реже, когда ничего не происходит**: 20 → 30 → 45 → 60 секунд. Новое
   письмо, возвращение на вкладку, смена папки возвращают к 20. Замерено: 4 опроса за
   150 секунд вместо 7 — в тишине втрое меньше обращений.

Что проверено и **не** сделано: оставшиеся 25 мс на запрос — это не проверка пароля
(включали `auth_cache_size`, разницы нет: 25,1 → 26,0 мс, откатили), а запуск процессов
Dovecot. Убрать это можно только переиспользованием соединений между запросами, а для
этого сначала придётся поднять `mail_max_userip_connections` (сейчас 10): одиннадцать
рабочих процессов упёрлись бы в предел, и у людей перестали бы подключаться телефон
и Outlook.

## 6. Скрытые механизмы: проверено, что не копят мусор

- **Автосохранение черновика** — пять сохранений подряд оставляют один черновик, а не пять.
- **Удаление письма** — уходит в «Корзину», из «Корзины» удаляется совсем.
- **Открытие письма с `?peek=1`** не отмечает его прочитанным.
- Большие «Черновики» у нескольких ящиков (48, 44, 38) — это импорт из Kerio от 13.09,
  а не наша работа: у всех одна дата сохранения.

### Что ещё ускорено (второй заход)

Разложили открытие страницы по частям — и нашли неожиданное:

| часть страницы | было |
|---|---|
| предел размера письма | **172 мс** |
| папки (IMAP) | 53 мс |
| список писем (IMAP) | 34 мс |
| настройки (БД) | 23 мс |

Предел размера письма брался из настроек почтового сервера, и ради одного числа
запускалось семь внешних программ (четыре запроса к amavis, плагины iredapd, postconf,
systemctl). Кэш жил 30 секунд — каждые полминуты кому-то доставалась медленная страница.
Спрашиваем только нужное значение, одной программой, и помним сутки: **172 → 0,5 мс.**

Список папок: счётчик писем спрашивался отдельной командой на каждую папку. Dovecot умеет
отдать всё разом (LIST-STATUS, RFC 5819): **52,6 → 39,7 мс**, одиннадцать команд вместо
двадцати одной.

Сборка переписки: для письма без переписки всё равно выполнялся запасной поиск по теме —
он написан для программ, которые не ставят ссылку на предыдущее письмо, но шёл всегда.
Теперь работает только в своём случае: **201 → 134 мс** по журналу сервера.

Итого страница почты: **199 → 110–130 мс**.

Отдельно стоит запомнить: первая версия «ускорения» списка папок **не работала** —
`array_walk_recursive` требует ссылку и не принимает приведение к массиву прямо в вызове,
функция падала, а ошибку ловил наш же `catch` и молча возвращал старый путь. Замер это
и показал. Теперь неудача быстрого пути пишется в журнал: тихий запасной путь не должен
скрывать поломку.
