# Подводные камни

Всё, что ниже, однажды уже сломало работу или стоило отдельного разбора. Читать до того,
как менять почтовое ядро, развёртывание или клиент веб-почты.

Связанные документы: [архитектура](architecture.md), [разработка](development.md),
[процессы](processes/README.md).

## Библиотека IMAP (webklex/php-imap)

- **Имена папок в IMAP — modified UTF-7**, а библиотека местами шлёт UTF-8. `Folder::move()`
  передаёт старое имя в UTF-8, сервер ждёт UTF-7: переименование идёт через протокол
  напрямую (`FolderTree::renameFolder`). `createFolder($path, false, true)` означает «имя уже в UTF-7».
  Имена, закодированные дважды, распутывает `FolderTree::unmangle()`.
- **Строки в кавычках режутся по пробелам.** `"31-Aug-2026 08:54:48 +0800"` превращается в
  значение `"31-Aug-2026` и мусорный ключ. Ответы FETCH читаются не по ключу, а по виду значения
  (см. `MessageSummary::receivedAt`, `summaryFromFetch`).
- **Без `UID` в FETCH ответ пустой**, не ошибка.
- **Пачка в двести писем возвращается пустой**, сорок — исправно. Всё, что читается пачками,
  читается по сорок.
- **LSUB не поддерживается.** Подписки читаются `listSubscribedFolders`.
- **Удалённое письмо** даёт `MessageHeaderFetchingException: no headers found`. Её надо ловить
  и отвечать 404, а не 502 (`MailAttachments`).
- **Не разбирает** адрес вида `root@host (Cron Daemon)`, письмо без `From` и без `Date`.
  Запасной разбор — `Mime::firstAddress`, `Mime::senderOf`, `MessageSummary::receivedAt`.
  Запасной путь должен быть и в списке, и при открытии письма, иначе данные «пропадают» только в одном месте.
- **Сбойный поиск портит соединение**: ответ приходит после таймаута, и дальше по нему читаются
  чужие ответы. После любой ошибки поиска — переподключение (`ImapQuery::searchUids`).

## Dovecot

- **Точка в имени папки — разделитель** Maildir++. «ivan.ivanov» станет папкой «ivan» с вложенной
  «ivanov». Имена папок с точкой отвергаются; правило «папка по отправителю» склеивает части адреса через «-».
- **Подписки не следуют за переименованием и удалением.** В Outlook и Thunderbird видны только
  подписанные папки, поэтому переименованная папка пропадала, а старая висела призраком.
  Подписки переносятся вручную (`FolderTree::resubscribe`), уборка — `mail:fix-subscriptions`.
- **Правила Sieve хранят путь папки.** После переименования или удаления папки `fileinto :create`
  создаёт её заново. Правила подтягиваются за папкой в `RuleFolders`.
- **Sieve выполняется только для входящих.** Правило «Кому содержит …» на отправленные письма не действует.
- **Флаг «прочитано» в общей папке один на всех** (нет `INDEXPVT`). Веб-почта в чужой папке
  по умолчанию не отмечает письмо при открытии (`MailStore::marksSeenOnOpen`).
- **Полнотекстовый индекс fts_xapian** отвечает только по From, To, Cc, Bcc, Subject, Message-ID.
  Поиск по другим заголовкам молча возвращает пусто. Когда индексатор дописывает индекс папки,
  поиск может ответить `NO [SERVERBUG]`; одна повторная попытка через 1,5 с это лечит.
- **Черновики Outlook** лежат без `From` и `Date`. После переноса из другой почты они могут
  оказаться во «Входящих».

## Разбор структуры письма

- Тело письма ищется по `BODYSTRUCTURE` (`Structure::bodyParts`). У писем
  `alternative(text/plain, related(text/html, картинки))` разметка лежит глубже текста.
  Отличать её от вложенного пересланного письма можно только по цепочке контейнеров
  (`chain`): alternative и related — то же письмо, mixed — вложенное.
- Картинка считается встроенной, только если на её Content-ID ссылается разметка
  (`Structure::isEmbeddedImage` + проверка `cid:`). Иначе она уходит в список вложений.
- Word и Outlook оставляют условные комментарии `<![if …]>`, HTMLPurifier показывает их текстом;
  вырезаются до очистки (`MailHtml::sanitize`).

## Отправка

- Черновик при сохранении получает новый UID. Письмо, собранное со старым UID, не найдёт вложений
  исходного черновика: сервер берёт их из актуального (`MailBuilder::keptAttachments`, 409 при потере).
- Облачные файлы публикуются до отправки; если отправка не удалась, они откатываются
  (`LocalFiles::discardTokens`, `discardForMessage`).
- Ошибки SMTP переводятся на человеческий язык в `Outgoing::smtpFailure`.

## Octane / RoadRunner и nginx

- Рабочие процессы Octane — **CLI-PHP**. Лимиты загрузки задаются в
  `/etc/php/8.3/cli/conf.d/99-mailadmin.ini`, а не в php-fpm. Иначе большие вложения получают 413.
- Три предела должны совпадать: `client_max_body_size` в nginx (и на внешнем прокси, если он есть),
  `http.max_request_size` в `.rr.yaml`, `post_max_size`/`upload_max_filesize` в CLI-PHP.
- Сайт веб-почты должен быть `default_server` на 443, иначе обращения по IP попадают на
  сайт файлового хранилища.
- Код в Octane живёт между запросами: статические кэши и синглтоны надо сбрасывать, иначе данные
  одного пользователя достанутся другому.

## Клиент веб-почты (Vue)

- **Порядок композаблов.** Значение из композабла, созданного ниже по файлу, нельзя передавать
  в композабл выше: временная мёртвая зона даёт белый экран. Передавать обёрткой
  `undoSend: () => undoSend()`. Тесты этого не ловят, ловит только проверка в браузере.
- Полоса прокрутки списка сбрасывается при смене страницы, папки, отбора и поиска, но не при
  фоновом обновлении и не при действиях над письмами.
- Картинки из текста письма просмотр отдаёт **ссылками на наш сервер**
  (`/mail/api/message/<папка>/<номер>/attachment/<n>?inline=1`, см. MessageBody). В исходящее письмо
  такая ссылка уйти не может: получатель её не откроет, а у черновика после сохранения меняется
  номер. Окно письма при открытии подставляет сами картинки (`Editor.embedServerImages`), сервер
  встраивает оставшиеся (`MailBuilder::embedServerImages`). Подстановка — не правка человека:
  иначе открытый и закрытый ответ оставлял черновик.
- `display` в служебных классах (`.desktop-only` и т. п.) не задавать: он перебивает `inline-flex`
  кнопок, и значок съезжает относительно подписи. Панель письма и шапка письма сжимаются по ширине
  области чтения (`@container mread`), а не окна — колонки тянут мышью.

## Развёртывание

- **Перед коммитом** проверять `git status --short | grep '^ D'`: однажды коммит удалил почти двести файлов.
- `deploy/update.sh` тянет ветку с GitHub; при сбое сети его достаточно запустить ещё раз.
- `postsuper` принимает один ID за раз: второй аргумент он считает именем очереди
  («invalid directory name»). В `mailadmin-ctl` операции с очередью идут циклом.
- Ничего, что требует root, приложение не делает напрямую — только через белый список
  `sudo mailadmin-ctl <подкоманда>`. Новую привилегированную операцию добавлять туда.
